# Yamux Load Test Sanity Guide

This document explains how to run the lightweight Yamux load test (`TestTunnelServerYamuxLoad`) to validate Phase 2 tunnel stability and concurrency.

---

## Goals

1. **Verify multi-stream stability**: ensure a single TLS+Yamux session can sustain dozens of concurrent streams.
2. **Exercise handshake and session registration**: the test uses the real `tunnel.Server`, `SessionManager`, and Control Stream handshake path.
3. **Provide reproducible steps**: make it easy for anyone to re-run the test locally or in CI.

---

## Test Overview

- Located in `pkg/tunnel/load_test.go`.
- Spins up a temporary TLS-enabled tunnel server with autogenerated certificates.
- Launches a simulated node that:
  - Establishes a TLS connection.
  - Opens a Control Stream and completes the JSON handshake.
  - Echoes payloads on multiple simultaneous Yamux streams.
- The test client opens `streamCount` (default `64`) concurrent streams via the Go SessionManager, writes random payloads (~8 KiB), and asserts the echoed data matches.

---

## Prerequisites

- Go 1.25+.
- No external services are required; certificates are generated on the fly.
- Ports `127.0.0.1:0` (ephemeral) are used automatically, so there is no fixed port reservation.

---

## Running the Test

Execute:

```
go test ./pkg/tunnel -run TestTunnelServerYamuxLoad -count=1
```

### Expected Output

```
ok  	github.com/grpc-mesh/grpc-mesh-server/pkg/tunnel	0.xxxs
```

Any failures will be reported with descriptive log lines (e.g., stream read/write errors or handshake failures).

---

## Key Metrics Captured

While the test itself doesn’t export Prometheus metrics, it indirectly validates:

- Successful Control Stream handshakes.
- Ability to open `streamCount` streams without backpressure.
- Payload integrity for each stream.

For runtime metrics during normal operation, ensure `server.metrics_address` is configured (e.g., `:9090`) so `/metrics` exposes tunnel counters and gauges.

---

## Troubleshooting

| Symptom | Likely Cause | Action |
| --- | --- | --- |
| `tls dial` failures | OS-level TLS restrictions or conflicting loopback port | Confirm Go version ≥ 1.25 and retry |
| `handshake failed` | Code changes in `control.Handshake` validation | Ensure test handshake includes required fields |
| Payload mismatch | Race introduced in echo handler | Re-run with `-count=1 -race` to pinpoint |

---

## Extending the Test

- **Adjust concurrency**: change `streamCount` in the test to stress higher fan-out.
- **Increase payload sizes**: bump `payloadSize` to evaluate window tuning (`tunnel.max_stream_window`).
- **Simulate timeouts**: set shorter `HandshakeDeadline` or stream deadlines to confirm retry/backoff behavior once Phase 3 heartbeat logic lands.
